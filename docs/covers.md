# public/covers/ — 自前で用意した書影の置き場

書影の解決（`src/lib/cover.ts`）は、このディレクトリの画像を **最優先** で使う。
openBD / Google Books より先に参照されるため、ここに置いた時点でそれが本番で配信される。

## ファイル名

`<13桁ISBN>.jpg`（ハイフンなし）。例: `9784150504106.jpg`

`.png` / `.webp` も認識するが、原則 `.jpg` を使うこと。
ISBN は記事の frontmatter の `isbn` と完全一致していなければならない。

## 法的な位置づけ（必読）

**ここに置いた画像は自サイトから配信される。これは書影（表紙デザイン）の複製および
公衆送信にあたる。** 外部APIが返すURLを参照するのとは法的な扱いが異なり、
「引用」で当然に正当化されるものでもない。したがって以下を前提とする。

## 運用ルール

1. **出版社へ書影掲載の許諾をメールで取得する。**
   掲載先URL・用途・掲載期間を明記して依頼し、**許諾の返信は記録として保存する。**
   許諾が取れていない書影をこのディレクトリに置いてはならない。
2. **書誌情報・出典を明記する。**
   書名・著者・出版社・刊行年を必ず記事上に表示し、書影の出所を明らかにする。
3. **削除要請には即応する。**
   出版社・権利者から要請があった場合は、該当ファイルを直ちに削除して再デプロイする。
   窓口は `/contact` に常時掲載しておく。

許諾が取れない書籍は、このディレクトリに画像を置かないこと。
その場合は `BookCover.astro` の縦組みフォールバックが表示される。
フォールバックは欠損の穴埋めではなく、そのまま成立する意図的な表示として設計してある。

## 取得済みURLのキャッシュ（`.cache/covers.json`）

外部APIから取れた書影URLは `.cache/covers.json` に残る（git には入らない）。
毎回引き直すと、記事が増えるほど一度に問い合わせる冊数が増えて
Google Books のレート制限（429）を踏み、**その回に引いた本だけが
フォールバックに倒れる**という不安定さが出るため。

書影が差し替わらないかは30日で見直す。手元で今すぐ引き直したいときは
ディレクトリごと消してよい（消しても引き直されるだけ）。

`public/covers/` に置いた自前の画像はキャッシュを通らない。
ここにファイルを足せば dev サーバーを再起動しなくても反映される。

同じ本の書影がページによって食い違っていないかは
`npm run check:covers`（`npm run verify` に含まれる）が dist/ を見て検査する。
