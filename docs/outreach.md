# 選者への声のかけ方（X・DM）

X などで面識のない相手に声をかけ、選書を集めるときの文面と原則。
応募フォームそのものの設計は `docs/apply-form.md`、
記事の作り方は `README.md` を参照。

---

## 送るリンク

- 詳細と応募フォーム: `https://book-media.pages.dev/apply`
- 運営について: `https://book-media.pages.dev/about`

**DMには2本とも載せる。** 役割が違い、相手が返信するかを決めるときに見るのは
`/about` のほうで、`/apply` だけだといきなり作業を求められた形になる。
逆に `/about` だけだと「で、何をすればいいのか」が分からない。

**Tally の直リンクは送らない。** `src/config.ts` の投稿導線でも決めているとおり、
何を書くのか・掲載の判断はどうなるのかを読んでからフォームに進んでもらう。

**`/about` を必ず添える。** 面識のない相手に依頼したとき必ず見られるページで、
ここの信用が可否を決める（`.dev/requirements.md` R10）。

## 聞き方の原則 — 「おすすめの本」とは聞かない

**❌「おすすめの本を教えてください」**
**❌「〇〇がご専門とお見受けし、専門分野の本を…」**
**✅「〇〇について書かれているのを拝見していて、〇〇に関心を持った人に薦める本を3冊、教えてください」**

相手の手間は「3冊挙げるだけ」で変わらないのに、自分の土俵になるぶん
**むしろ答えやすい**。そのうえで次の2つが保たれる。

- **なぜこの人に聞くのか**が立つ（`README.md`「企画のお題を立てるときの注意」で
  ❌「自分のバイブル5冊」を挙げているのと同じ理由。誰でも語れる問いにすると
  有名な本が並び、差別化が消える）
- **`topic`（分野）をこちらで割り当てられる。** 相手が書いている話題から決まる

### 「専門」「専門性」という語をDMで使わない

**X には専門性を明示していない人が多く、「ご専門は」と聞いた瞬間に
「自分は名乗れるほどではない」と降りられる。** これは相手の資格の問題ではなく、
**自己申告を要求している**ことによる摩擦。

解き方は、**相手に名乗らせず、こちらが観察した事実を差し出すこと。**
X で声をかける相手は、肩書きを出していなくてもタイムラインに証拠が出ている
（その話題を何年も書いている、その分野の本を読み続けている）。
それを**こちらが文章にして、相手には「合っていますか」とだけ確認してもらう。**

> **`credentials`（詳しい理由）は必須のまま維持する。** `README.md`
> 「`credentials` を必須にしている理由」のとおり、選者の知名度がゼロの初期段階では
> **ここが読者にとって唯一の手がかり**で、空だと「知らない人のおすすめリスト」になり
> ブクログのレビューと区別がつかなくなる。
>
> **ただし本人が書く必要はない。** 書き方の例に挙がっている
> 「在野で〇〇史を調べており、Xで継続的に書いている」は、
> **本人が自称しなくてもこちらが観察して書ける文**。下書きして確認稿に載せ、
> 承認をもらえばよい。掲載前の本人確認はどのみち必須プロセスなので、
> 承認の場は最初から確保されている。相手の作業は「はい」だけになる。

> **`topic: おすすめの本` を新設しない。** 記事タイトルの型が
> `〈選者〉が選ぶ、〈topic〉のN冊` なので「おすすめの本のN冊」になって崩れる。
> さらに全記事が1つのテーマページに積み上がり、`/topics/<名前>/` が
> 唯一のアーカイブ軸として機能しなくなる。分野をタグに逃がす案も、
> `subtopic` / `tags` はページを持たない設計であるうえ、分野名は
> `topics.json` 側の語彙なので**同じ語の二重管理**になる。
>
> **分野が本当に絞れない記事の受け皿はもうある** — 大トピック `人がすすめる本`
> （小トピック＝大学・研究者／作家・翻訳者／俳優・声優／芸人 …）。
> ただし**分野が絞れる記事は分野側に置く**。粒度で迷うときは `〇〇全般` を使う。

## 2つのトラック — 人を証明するか、本を証明するか

X には肩書きを明示していない人が多い。**その相手に「専門」を求めるより、
証明の対象を人から本へ移したほうが通る。** 聞き方を2本持っておく。

| | A. 分野トラック | B. 無名の良書トラック |
|---|---|---|
| 向く相手 | 研究者・編集者・書店員など、詳しさが外から見える人 | 肩書きを出していないが、よく読んでいる人 |
| 何で読者を納得させるか | **選者の詳しさ**（`credentials`） | **本そのものの珍しさ** |
| 聞き方 | 「〇〇について書かれているのを拝見していて…」 | 「あまり知られていないけど読んでよかった本を3冊」 |
| `topic` | 分野（`文学` `経営学` …） | 分野に寄れば分野。寄らなければ `あまり知られていない良書` |
| `credentials` | 研究・仕事・発信 | **「〇〇を読み続けている」**（答えから自然に出る） |

**B は README が ✅ とするお題の型。** 「企画のお題を立てるときの注意」に
✅「絶版だが読まれるべき本」が挙がっており、B はこれとほぼ同じもの。
❌ とされた「自分のバイブル5冊」と混同しないこと。**失敗の仕方が逆**で、
❌ の問題は「誰でも答えられる**うえに有名な本が並ぶ**」ことだった。
B は誰でも答えられるが、**集まるのは無名の本**で、
`.dev/business-plan.md` の言う価値（その道に詳しい人しか知らない本）に直撃する。

### B では質問を2段にする

```
よく読まれているジャンルってありますか？

その中で、あまり知られていないけど読んでよかった本を
3冊挙げていただけないでしょうか。
```

1問目を挟むだけで3つ同時に取れる。

- **`topic` が取れる**（「専門」と違い「よく読むジャンル」は名乗る負担がない。
  **聞いている情報はほぼ同じなのに心理的な負荷がまるで違う**）
- **`credentials` の素材が取れる**（「〇〇を読み続けている方」）
- **3冊のまとまりが保証される。** 1問目が無いと SF・料理・経営学が
  バラバラに返ってきて、見送り基準③（記事としてのまとまりが見えない）に当たる

### B のDM文面 → 「そのまま送れる原稿 ①」

### B の記事の `topic`

1. **ジャンルが1つに絞れた → 通常どおり分野の `topic`。こちらを優先**
2. **どうしても絞れない → `あまり知られていない良書`**（`topics.json` に追加済み。
   小トピックに31分野を入れてあるので、寄っているジャンルは `subtopic` に残せる）

**2に流しすぎないこと。** `/topics/` は topic だけがページを持つ唯一のアーカイブ軸で、
ここに全記事が集まると機能しなくなる。応募フォームでも**選択肢の末尾に置き
「（分野が絞れない場合）」と添える**（`docs/apply-form.md`）。

---

### 応募時に聞くことと、記事のスキーマは一致していなくてよい

分野の割り当ては**記事化のときに運営が1記事1回判断すれば済む**。
フォームで31択を選ばせているのは往復を減らすためであって、
相手に選ばせないと決められないからではない。
**声のかけ方を緩めるためにスキーマを触る必要はない。**

## そのまま送れる原稿

**リンクは2本セットで載せる。** `/apply`（何を書くのか・掲載の判断）と
`/about`（誰が運営しているのか）は役割が違い、相手が返信するかを決めるときに
見るのは後者。**面識のない相手にはこの2つが揃っていないと信用の判断ができない。**

**〔◆〕は必ず埋める。** ここがテンプレのままだと一斉送信と分かって返信率がゼロになる。

### ① 主力：Bトラック（肩書きを出していない人へ）

```
はじめまして。Skrinia（スクリニア）という、本に関するメディアを運営している
@dokugaku_zin と申します。突然のご連絡失礼いたします。

Skriniaは、何かを学ぶときにおすすめする本をリスト形式で紹介するメディアになっており、さらにその中からあまり世の中には知られていない良書をもっと世の中に紹介することを目的に運営しています。

今回は、投稿を拝見し、ぜひおすすめの本を紹介していただきたく、ご連絡いたしました。

選書依頼の内容といたしましては、『[アカウント名]様がお詳しいジャンルにおいて、読んでよかった本』を3〜5冊程度、教えていただけますでしょうか。基本的にどんな本でも結構ですが、もし可能であれば、「あまり知られていないけど、個人的に読んでよかった本」も選書リストに入れていただけますと幸いです。

お答えいただいた内容につきましては、公開前に必ず原稿をお送りしご確認いただいてから掲載させていただきます。

以下が応募フォームへのURLと、Skriniaについて紹介しているサイトURLになっております。選書内容は応募フォームからご入力ください。

何かご質問などございましたら、ご返信ください。

▼ 応募フォーム
https://book-media.pages.dev/apply
▼ Skriniaについて 
https://book-media.pages.dev
```

### ② Aトラック（大学教員・研究者・編集者・書店員など、詳しさが外から見える人へ）

**①誰か ②なぜあなたか ③何をしてほしいか ④どれくらいの手間か** を順に置く。
①と同じ流れのまま、**依頼の理由を「投稿を見て」から
「その分野を学びたい人に届けたいから」に差し替える**のがAトラックの違い。

```
はじめまして。Skrinia（スクリニア）という、本に関するメディアを運営している
@dokugaku_zin と申します。

いつもの投稿を拝見して、ぜひおすすめの本を紹介していただきたく、ご連絡いたしました。[専門分野]をこれから学びたい人に向けて、薦めていただける本を3冊程度、ご紹介いただけないでしょうか。

書名だけで結構です。それぞれ一言ずつでも理由を添えていただけると助かりますが、
難しければこちらでお話を伺って書く形でも構いません。
出版社や版はこちらでお調べしますので、ご記入は不要です。

・ご所属・お名前の表記は、ご本人のご希望のとおりに掲載します
・公開前に必ず原稿をお送りし、ご確認いただいてから掲載させていただきます
・学生や、これからその分野に入る方に向けた案内として掲載しています

以下にご入力いただけるフォームへのURLと、このメディアについて紹介している
ページへのURLを載せております。もしよろしければ、フォームご入力の前に
一度このメディアについて知っていただけると嬉しいです。

▼ 詳細と応募フォーム
https://book-media.pages.dev/apply
▼ このメディア・運営について
https://book-media.pages.dev/about
```

**①（Bトラック）との違いは4点だけ。**

- **「肩書きやご所属は要りません」を書かない。** ①では応募のハードルを下げる一言だが、
  肩書きのある相手に言うと「名前を出さなくていい程度の話」と読めてしまう。
  代わりに**「ご希望のとおりに掲載します」**（表記の主導権は本人にある）と置く
- **「あまり知られていない本も」と添えない。** 研究者に無名の本を求めると
  「一般向けではない本を挙げろ」という要求に読める。
  無名の本を拾うのは**「いちばんよかった1冊」の質問**（2通目）の役割
- **取材（お話を伺って書く）を先に提示する。** 大学教員はまとまった文章を書く時間が
  最も取りにくい。`.dev/business-plan.md` では寄稿がデフォルトだが、
  **この層に限っては取材の選択肢を最初に見せたほうが返信が来る**
- **誰に届くのかを書く。** 「学生や、これからその分野に入る方に向けて」は、
  教育の一環として引き受けやすい理由になる

### ①② に共通する原則

- **「ご専門は〇〇とお見受けし」と書かない。** ②の相手には肩書きがあるが、
  それでも**こちらが読んだもの**（研究・著書・投稿）を具体的に挙げる。
  肩書きへの言及は誰にでも書けるが、実際に読んだ証拠は書けない
- **「3冊程度」と数を示す。** 「3冊以上」は上限の判断を相手に投げてしまう。
  3冊程度なら即答でき、挙げられる人は勝手に増やす
- **字数の要求を後ろに下げる。** まず3冊もらえば会話が始まる。
  100〜200字という数字はここでは出さない（フォームと2通目で出す）
- **〔◆〕は必ず埋める。** テンプレのままだと一斉送信と分かって全滅する。
  ②では特に致命的で、**論文や著書を読んでいない相手に「拝見しており」は書かない**

### `credentials` は下書きして渡す

理由を書いてもらえないまま話が進みそうなときは、こちらから提案する。

```
記事にはお名前のところに一言、
「〇〇について長く書かれている方」といった紹介を添えています。
こちらで下書きしてお送りしますので、
直したいところがあればそのときに教えてください。
```

### ③ 返信が来たとき — フォームに戻さない

DMで書名だけ返ってきたら、その場で続けるのが最も歩留まりがよい。
フォームは相手が「まとめて書きたい」と言ったときに出す。

```
ありがとうございます。〔◆書名3つ〕ですね。

もしよろしければ、それぞれ100〜200字ほどで
「どんな本か／なぜ挙げたか」を伺えますか。長さは目安で結構です。

あわせて2点だけ:

・この3冊の中で、いちばんよかった1冊はどれでしょうか。
　その決め手を150字ほど伺えると助かります
　（迷われた場合、あまり知られていない本だと嬉しいです）

・記事に載せるお名前と、その本を薦められる背景を一言
　（「〇〇を10年読んでいる」程度で十分です。
　　書きにくければこちらで下書きしてお送りします）

原稿ができましたら公開前にお送りします。
ご連絡先のメールアドレスもお教えいただけますか。

まとめて書きたい場合はこちらのフォームからでも:
https://book-media.pages.dev/apply
```

**「いちばんよかった1冊 ＋ その理由」を取りこぼさない。**
これが無いと `bestReason` が埋まらず記事を公開できず、
`/hidden`（知る人ぞ知る本）にも載らない。

**メールアドレスは必ず回収する。** 匿名可のメディアなので
「本人が原稿を見て了承した記録」が唯一の担保であり、
訂正・削除要請の窓口でもある。**DMだけで完結させない。**

## 避ける言い回し

| 言い回し | 理由 |
|---|---|
| 「おすすめの本を教えてください」 | 誰でも答えられる問いになり、有名な本が並ぶ |
| 「ご専門は〇〇とお見受けし」「専門性を活かして」 | Xでは専門性を明示していない人が多く、**名乗れるほどではないと降りられる**。観察した事実で置き換える |
| 「5冊」 | 3冊以上に緩和済み。5と言うと答えられない人が黙って離脱する |
| 「ご執筆いただけませんか」 | 依頼の重さが跳ね上がる。実際の負荷は「3冊＋各100〜200字」 |
| 謝礼・「ご著書を紹介します」 | `.dev/business-plan.md` でやらないと決めている（自著が混ざると宣伝媒体になる） |

## 声かけを始める前に確認すること

- **独自ドメイン。** 公開URLが `book-media.pages.dev` のままだと、
  コールドDMでリンクの信用が落ちる。後から変えると X の OGP キャッシュにも当たるため、
  **当てるなら声かけを始める前**
- **`SITE.contactEmail` が実在すること**（見送りの連絡・削除要請の窓口）
- **応募フォームの必須設定**（所属・X・記事のテーマ・その他は任意のはず。
  詳細は `docs/apply-form.md`）
