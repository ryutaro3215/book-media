# Plan — fivebooks（仮称・名称選定中）
status: approved
updated: 2026-08-04
stack: Astro（Content Collections + MDX）/ TypeScript / Zod / **Tailwind CSS v4**（`@tailwindcss/vite`。CSS-firstの `@theme` でデザイントークンを定義）/ Satori + resvg-js（OGP画像のビルド時生成）/ Cloudflare Pages（ホスティング）/ Cloudflare Web Analytics
inputs: business-plan.md (approved) / requirements.md (approved) / design-brief.md (approved)

## 技術選定の記録

- **Astro**: ユーザー承認済み（比較提示 → 選択）。Content Collections の Zod スキーマ検証が「5冊固定の構造化frontmatter」という要件に直撃で応えるため
- **Cloudflare Pages**: 選択の余地なし。Vercel Hobby と GitHub Pages は**規約で商用利用を禁止**しており、business-plan.md の「将来収益手段を探す」方針と両立しない
- **Tailwind CSS v4**: ユーザー指定（2026-08-04）。当初は素のCSSを想定していたが、利用技術に制限がないため変更した
  - **v4 の CSS-first 設定（`@theme`）で design-brief.md のトークンを一元定義する。** 配色・行間・カラム幅を Tailwind のテーマトークンとして宣言し、**コンポーネント側では任意値（`text-[#2F4A3F]` のような直書き）を使わない**。これによりトークンからの逸脱をレビューで検出できる
  - `@apply` の多用は避け、繰り返しはAstroコンポーネントとして切り出す
  - Claude Design のエクスポートHTMLがTailwindでない記法で来た場合、実装時にトークンへ置き換える（`design/` のHTMLは見た目の正であって、記法の正ではない）
- **書影のフォールバック実装方針**: design-brief.md では「ビルド時に生成した文字組みの面」としていたが、**ページ内表示はCSSコンポーネントで実装する**（画像生成より軽く、レスポンシブに追随し、テキストが選択・検索可能になるため）。Satori は OGP画像の生成にのみ使う

## external_skills

- **dev-design**: design-brief.md の所有者。デザイン変更時は本skillでブリーフを更新してから実装に反映する（T4/T6/T7/T8 に関連）
- **fixing-accessibility**: T11 のアクセシビリティ検証で使用。見出し階層・コントラスト比・キーボード操作の監査
- **baseline-ui**: T3・T4・T6・T7 で使用。Tailwind プロジェクトのタイポグラフィスケール強制・レイアウトのアンチパターン検出・コンポーネントのアクセシビリティ検査に使う。**design-brief.md の指定と競合した場合は design-brief.md を優先する**（本プロジェクトは行間1.9・カラム660pxという固有の値を意図的に採用しているため）
- **frontend-design**: T3 で使用可。デザイントークンを落とす際の指針として参照する（design-brief.md の指定が優先）
- **dev-security**: リリース前の監査（plan外・リリースゲート）
- **dev-docs**: README・セットアップ手順の作成（plan外・リリース後でよい）

  - 取れない本は珍しくない（実測: 記事中の `9784000052092`・`9784003210123`・

  1. **書影の解決は `src/lib/cover.ts` にさせる。** `.mjs` から TypeScript は読めないが、

## T28: 書影は登録時に一度だけ引き、記録をリポジトリに持つ（完了）

- goal: **表示のたびに外部APIを叩くのをやめる**。書影URLを
  `src/data/covers.json` に記録し、ビルドと dev はそれを読むだけにする
- 背景（実測した不具合）:
  - **Google Books の無料枠は1日1,000件。** 記事の一括生成で書誌照会を
    数百回走らせた日に使い切り、**書影が一斉に消えた**（実測: 51/51 が 429）
  - 429 は `null` になり、「書影が無い」と**区別がつかなかった**
  - **本番ビルドは Cloudflare 上で走る。** そこで上限に当たれば、
    手元では見えているのに本番だけ落ちる
  - キャッシュが `.cache/`（`process.cwd()` 基準・git 管理外）だったため、
    **ワークツリーを移ると空**になり、前は映っていた本が映らなくなった
- **決めたこと**:
  1. **記録するのはURLだけ。画像はダウンロードしない。**
     自サイト配信は複製・公衆送信にあたり出版社の許諾が要る（`docs/covers.md`）。
     一括ダウンロードは**そのルールを機械的に破る**ことになる。
     許諾が取れた本は従来どおり1冊ずつ `public/covers/` に置く
  2. **記録はリポジトリに入れる**（`src/data/covers.json`）。
     `.cache/` では cwd 依存で、CI と手元とワークツリーで別物になる
  3. **`url: null`（書影が無い）も記録する。** 残さないと絶版本を毎回引き直す
  4. **429・タイムアウトは記録しない。** 本の性質ではなくそのときの都合であり、
     焼き付けると本当は書影がある本が出なくなる
  5. 引くのは**「/admin で取得を押したとき」と `npm run sync:covers`** だけ
- acceptance: **達成済み**
  - `npm run build` が外部APIを1回も叩かず、記録から書影を解決する ✓
  - 上限超過の状態で `npm run sync:covers` を実行 → **51件すべて「取得できず」となり、
    記録は170件のまま変わらない** ✓（以前はここで全部が「書影なし」になっていた）
  - `npm run verify` 通過・`書影の一貫性: 5冊 / 11箇所 — すべて同じ結論` ✓
- depends: T27
- 残し: URLは腐りうる。`npm run check:covers` にリンク切れの検査を足すかは、
  実際に腐ってから判断する（いま入れると毎回218件のHEADリクエストを撃つことになる）

## T29: /admin で下書きと公開済みを分ける（完了）

- goal: `/admin` の記事一覧で、**書きかけと公開済みが一目で分かれている**状態にする
- 背景:
  - 現在 `<select id="open-article">` に**全記事を1列で並べている**。
    `[下書き] タイトル（日付）` と接頭辞を付けているだけ
  - **記事は45本（公開1 / 下書き44）。** 今後も増える。
    プルダウン1つに数十件が混ざると、**開きたい記事を探すこと自体が作業**になる
  - 実際の作業は「書きかけの続きを書く」が大半で、公開済みを開くのは
    直しのときだけ。**頻度が違うものが同じ場所にある**
- **決めたこと**（2026-08-08・実装済み）:
  1. **分け方 — `<optgroup>` で区切り、絞り込みと併用する。**
     区切るだけでは下書き44本がそのまま残る。**これは「分ける」より
     「探せる」の問題**だったので、絞り込みを合わせて入れた
  2. **並び順 — 下書きは最後に触った順、公開済みは公開日の順。**
     探し方が違うので並べ方も変える。書きかけを探すときに効くのは
     更新の新しさで、公開済みはいつ出した記事かで思い出す
  3. **絞り込みを付けた。** タイトル・大トピック・小トピック・タグ・選者で引ける
  4. **公開済みは隠さない。** 隠すと直したいときに一手増える。
     下書きを先に置き、件数を出すことで取り違えを防ぐ
- acceptance: **達成済み**
  - 下書き44 / 公開済み1 が optgroup で分かれ、件数が出る ✓
  - 絞り込みの実測（45本に対して）:

  - 下書きが先頭・最後に触った順、公開済みが末尾 ✓

## T30: 哲学者の人名タグを入れる（完了）

- goal: `src/data/tags.json` に**著名な哲学者の人名**を入れ、

    事実上の分野名で、「カント入門」「ニーチェを読む」という引き方が成立する。
    小トピック（`哲学史` `倫理学` `形而上学`）は**問いの領域**を切るが人物では切れず、
    役割が重ならない

     「ラマチャンドランの本」を探すのは**著者検索**であって分野の横断ではない

     啓蒙思想家・社会科学者は外した（福沢諭吉・アダム・スミスを入れていない）
  3. **表記は1人1つ。** 姓のみが慣例なら姓のみ、姓だけで紛れるならフルネーム。
     欧文フルネームは中黒、原語がハイフンの複合姓は `=`、日本・中国の人物は中黒なし
  4. **東洋・日本を落とさない。** 大トピックに「哲学」「宗教学」がある以上、
     西洋だけ入れると扱う範囲と噛み合わない
  5. **落とした `プラトン` `カント` を元の記事に戻した**
