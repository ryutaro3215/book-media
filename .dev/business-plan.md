# Business Plan — fivebooks（仮称）
status: approved
updated: 2026-08-05

## 一言（10語以内）
その道に詳しい人が選ぶ、この分野の本

## 【コンセプト変更の履歴】

### 2026-08-05（第3回・現行）: 「5冊ちょうど」→「3冊以上」

**決定**: 記事に載せる本の冊数を、**5冊固定から3冊以上（上限なし）に変更した。**
スキーマの `z.array(bookSchema).length(5)` を `.min(3)` に緩和し、
記事ページ・OGP画像・JSON-LD・CLI の冊数表記をすべて**実際の冊数から動的に生成**する形にした。

**変更理由**: 第2回の変更（「埋もれた本」を必須条件から外した）と同じ構造の問題。
**事業最大のリスクは「記事が出ないこと」**であり、5冊固定は選者に対して
「ちょうど5冊ひねり出す」ことを要求する。分野によっては本当に薦めたい本が3〜4冊しかなく、
数合わせの1冊が混ざれば記事の質そのものが下がる。逆に7冊語りたい選者を5冊に削らせる理由もない。
冊数の下限を3に置いたのは、2冊以下では「選書」として成立しないため。

**失うもの（正直に記録する）**:
- **識別子としての固定形式が消える。** 「5冊」はこのメディアの名前・タイトル雛形・OGP画像・
  URL共有時の見え方すべてに埋め込まれた**単一の識別子**だった。可変にすると、
  記事ごとに見た目の型が揺れ、「あの5冊のメディア」という記憶のフックが失われる
- **原則11（一つのことだけをする）の担保が消える。** 分野を絞らない方針（2026-08-05確定）のもとで、
  原則11は「分野」ではなく**「5冊という形式」で担保する**と明記していた。
  冊数が可変になった時点で、**このメディアが「一つのことだけをしている」根拠は形式面から失われ、
  残るのは「選者の実名と専門性」だけになる**
- **差別化の1点目が弱まる。** 差別化3点のうち「5冊セットという固定形式」は
  「選者が選んだ本のセット」という、より一般的な形に後退する。
  これは HONZ・書店フェア・note の選書記事との距離が縮まることを意味する
- **仕組みで守れなくなる。** `.length(5)` は4冊でも6冊でもビルドを失敗させる**強制装置**だった。
  以後、記事の形式的な一貫性は運用で守るしかない（第2回で `whyUnknown` を外したときと同じ構造）

**オーナーへの伝達と決定**:
「**5冊固定は Five Books が17年守っている商品性であり、可変にすると識別子が弱まる**」
という論点は既にオーナーへ伝達済みであり、**それを理解したうえでの決定**である。
記事が出ないリスクを、識別子の強度より優先した。

**今後の観測点**: 実際に公開された記事の冊数分布を見る。
大半が5冊に収束するなら実質的な損失は小さい。3〜4冊が多数を占めるなら、
形式による識別子は完全に失われたものとして、代替の識別子（UI・OGP・編集方針）で作り直す。

### 2026-08-05（第2回・現行）: 「埋もれた本」を必須条件から編集方針へ移した

**主軸は「いい本を広める」。** そのうえで、**あまり知られていない本も積極的に
紹介していく**——これがこのサービスを作った動機であり、編集方針として維持する。
ただし**1冊ごとの必須条件ではなくなった**。

**きっかけ**: 1本目の記事（統計学）を書こうとしたところ、選んだ5冊が
『統計学入門』（東大出版会）など**定番の名著**であり、必須項目だった
「この本が知られていない理由」が**書けなかった**。
「有名でないこと」を全冊に課すと、**書ける記事が極端に狭まる**ことが分かった。

**判断**: 事業最大のリスクは「記事が出ないこと」。
全冊に条件を課すのをやめ、**「いい本を広める」を主軸に、埋もれた本は
編集方針として積極的に扱う**形にした。

**構造上の変化（正直に記録する）**:
- `whyUnknown` 必須という**記事フォーマットに埋め込んだ仕掛けが消えた**。
  今後「埋もれた本も紹介する」は**運用で守るしかない**（仕組みで守れない）
- 原則19（誰も見たことがないもの）の充足度は下がる。
  「専門家が5冊挙げる」だけを見れば **Five Books と同型**であり、
  書店フェアや大学の推薦図書リストとも競合する
- ただし**編集方針として埋もれた本を扱い続ければ、蓄積が差別化になりうる**。
  「定番も、埋もれた本も、どちらもその道の人が選んでいる」という状態を作れるか
  が焦点になる

**差別化（現行）**:
1. ~~5冊セットという固定形式~~ → **選者が選んだ本のセット（3冊以上）という形式**（2026-08-05 第3回で緩和。上記参照）
2. 選者の実名と専門性
3. 一次取材（寄稿）
4. （蓄積次第）**あまり知られていない本を継続的に扱っていること**

### 2026-08-05（第1回）: 学術書 → 埋もれた本
当初は「学術書の入門ガイド」だったが、**「広告や話題性では世に出ないが、
本当に面白い本」を発掘して広げる**方向へ変更した。
上記のとおり、この方向は第2回で撤回している。

**両回を通じて変えていないもの**: 選者の条件。
**選者の専門性は手放さない。** 「なぜこの人の推薦を信じるのか」が
このメディアの中核であり、ここを緩めるとブクログのレビューと区別がつかなくなる。
（ただし2026-08-05 に「肩書きは問わない」へ緩和済み。下記参照）

## 課題と顧客
- 誰の: **ある領域を本気で学びたいが、何から読めばよいか分からない人。** 具体的には、専攻外の領域に入門したい大学院生・学部生、知的好奇心が強く読書量が多い社会人。※「顧客像の具体化」は依然として未検証（オーナー自身以外の実在顧客に未接触）
- 何の課題: 年間7万点以上の新刊が出るが、書店の平台・Amazonのランキング・広告に出るのは一部のみ。**良い本が埋もれる構造がある**。現在の解決手段は X/note/書評/知人の口コミを自力で探すことで、探索に月数時間。金銭支出は **0円**（＝金銭的な痛みは存在しない。検証の結果「払っていない」ことが確認済み）
- 自分ごとか: yes（オーナー自身が「その分野の専門家が数冊紹介する」コンテンツの熱心な読者。最初の読者かつ最初の編集者になれる）

## 解決策とスコープ
- やること（1つ）: **その領域に詳しい人に「その領域を学ぶための本（3冊以上）とその理由」を書いてもらい、選者の名前と文脈つきで公開する Web メディア**
- **編集方針**: 定番の名著だけでなく、**あまり知られていないが良い本も積極的に紹介する**。
  これがこのサービスを作った動機。ただし1冊ごとの必須条件にはしない
  （課すと書ける記事が極端に狭まることが実際に分かったため）
- **選者の資格（2026-08-05 改定）**: **その領域に詳しい人。肩書きは問わない**
  - 研究者に限らず、**在野で研究を続けている人・その領域を長く読み続けている人・編集者・翻訳者・書店員・実務家**を含む
  - **【改定の理由】** 当初は「公開された実績がある人」に限り、実績が公開されていない人を除外していた。しかし**「その道の人しか知らない本」を知っているのは肩書きの有無とは別**であり、学者に絞ると母数が狭く、かつ多忙で断られやすい。コンセプトと整合しないため条件を広げた
  - **ただし「なぜその領域に詳しいのか」の記述は必須のまま維持する**（`credentials`）
    - 理由: 選者の知名度がゼロの初期段階では、**ここが読者にとって唯一の手がかり**になる。空だと「知らない人のおすすめリスト」になり、ブクログのレビューと区別がつかなくなる（差別化の中核が消える）
    - 書くコストは1〜2文であり、空欄を許す利得より空欄が生む損失の方が大きいと判断した
  - この基準の利点: ①読者がプロフィールから実績を辿って検証できる ②オーナーがXで選者を探す際の絞り込み条件として機能する
  - **【2026-08-05 改定】** 資格を「肩書きを問わない」に広げたため、①の「実績を辿って検証できる」も
    「**読者が『この人の話なら聞いてみたい』と判断できる材料がある**」に読み替える。
    `credentials` は自由文字列でリンクを持たないため、厳密な検証経路は
    選者プロフィールの X アカウント・サイトURLに依存する。
    構造化（リンク付きの配列）は選者が増えて記述がばらつき始めたら再検討する
- **「知られていない」の判定方法**: 定量基準（発行部数・レビュー数）はデータ取得が困難で運用が回らないため、**取材依頼時にその旨を伝え、選者の判断に委ねる**
  - ~~歯止めとして「この本が知られていない理由」を必須項目にする~~ → **2026-08-05 撤回。**
    全冊に課すと書ける記事が狭まりすぎるため項目ごと削除した。
    「埋もれた本も紹介する」は**編集方針として運用で守る**
- やらないこと:
  - ユーザー投稿機能（フェーズ2以降。コールドスタートで死ぬため初期は作らない）
  - フォロー / タイムライン / いいね等の SNS 機能（同上）
  - 読書記録・進捗管理・本棚機能（読書メーターの領域。原則11に反する）
  - 一般小説・ビジネス書のレコメンド（学術寄りに限定）
  - 書影の無断掲載、他者の選書リストの丸ごと転載（引用の範囲＋出典リンクに留める）
  - ネイティブアプリ（Web のみ）
  - 決済・課金機能（現時点で収益手段が未確定のため）

## 差別化
- 乗り換える理由（1文）: **ブクログには「誰が薦めたか」がないが、ここにはその道の専門家の実名と、本人が語った選書理由がある。**
- **差別化は次の3点に絞る（2026-08-05 確定）**:
  1. **選者が選んだ本のセットという形式**（2026-08-05 第3回までは「5冊ちょうど」固定だった。緩和の経緯と失ったものは【コンセプト変更の履歴】参照）
  2. **選者の実名と専門性**
  3. **一次取材（本人に語らせる）**
- ※「note等は本の専用メディアではないので埋もれる」という論点は**差別化としては採用しない**。短期的にはむしろ逆（noteには内部流入があり、無名の独立サイトより発見されやすい）。専門メディアとしてのアーカイブ蓄積による検索優位は1〜2年先の話であり、立ち上げ期の根拠にはならない
- 競合:
  - ブクログ（無料 / 最大の競合。ただし選者の権威と文脈がない）
  - 読書メーター（無料 / 記録系のため直接競合ではない）
  - HONZ・note・X 上の選書記事（無料 / 断片的で横断検索できない）
  - 各大学の推薦図書リスト（無料 / 更新されず、選書理由が薄い）
- 堀（moat）: **DM 聞き取りによる一次情報**。ネット上の既存情報の集約は初期の母数作りに使う燃料であって、差別化要因ではない（原則19: 集約サイトは共有されない）

## 価格
- モデル: **現時点では収益化しない**（無料メディア）
- 価格: 0円。オーナー判断により「まず読者を集め、規模が出てから収益手段を探す」方針を採用。※原則1・8・27・32 を意図的に破っている（下記参照）
- 検証済みで却下したモデル:
  - 出版社広告: 月10万PV到達が前提で、到達しても月5万円規模。営業サイクルが個人開発者の時間を食い、選者（学者）の心証も悪化させるため却下
  - Amazon アソシエイト: 書籍3% = 1冊約60円。月10万円には月1,667冊の購入発生が必要で、広告と同じトラフィックの壁
  - 買い切りの選書ガイド（3,000円）: **オーナー自身が「買わない」と判断**。自分が買わないものは他人も買わないため却下

## 流通・検証
- 最初の10人への到達ルート:
  1. X で学術系アカウント（研究者・大学院生・熱心な読書家）に DM で取材依頼
  2. 依頼の形は「投稿してください」ではなく **「あなたの分野の必読書を取材させてください。〇〇さんの回として公開します」**（無償労働の依頼ではなく露出の提供に変換する）
  3. 大学内の既存関係（指導教員・ゼミの先輩・研究会の知人）※人数は **未検証**
  4. 公開した記事を選者本人が X で共有 → その分野の読者に届く（選者経由の配信が主要な流入導線）
- **選者への依頼方式（2026-08-05 確定）**:
  - **デフォルトは寄稿**（選者に書いてもらう）。理由: 取材形式はオーナーの工数が1本あたり2〜3時間（聴取・文字起こし・執筆）かかり、記事10本で20〜30時間に達して持続しないため
  - **ただし相手が望めば取材も受ける。** 依頼文には「お書きいただくことも、お話を伺う形でも構いません」と両方示して選ばせる
  - 経路別の想定: **こちらからDMで依頼**（面識なし・多忙な人）→ 取材の方が断られにくい／**応募フォーム経由**（R16）→ 意欲があるので寄稿で成立
  - **注意点（実測ではなく一般則）**: 相手の工数は「話す＝30分」に対し「書く＝2〜3時間」で、**執筆依頼の方が重く、かつ遅延しやすい**。それでも寄稿を既定とするのはオーナー側の工数を優先した判断
  - **寄稿の場合はテンプレートを必ず渡す**（各冊300〜600字の選書理由／選者プロフィールにその領域に詳しい理由を含める）。指定なしだと分量・粒度・文体がばらつき、UI/UXで作った統一感が損なわれる
  - **「読みやすさのため体裁を整えさせていただく場合があります」と事前に伝える**（事後に文章へ手を入れるのは角が立つため）
  - **差別化への影響**: 全記事を寄稿にすると差別化の3点目「一次取材」が消える。①選書セットという形式 ②選者の実名と専門性 は残るため致命傷ではないが、強みは弱まる（記録として明示）
- **インセンティブ設計（金銭以外）**:
  - **やらないこと**: 謝礼を払う（Five Books は1本$400で17年赤字含み）／「あなたの著書を紹介します」と約束する（選書に自著が混ざるとメディアが宣伝媒体になり、コンセプトが死ぬ）
  - **依頼の主語を変える**: 「あなたのために露出を提供する」ではなく「**あの本のために語ってほしい**」。専門家は「この本が絶版なのは惜しい」という思いを持っていることが多く、自己利益ではなく使命感に訴える方が強い。かつメディアのコンセプトと一致するため嘘がない
  - **完成品を先に見せる**: 「こういうメディアを作ります」ではなく「こういう形で掲載されます」と実物のURLを示す。→ **1本目はオーナー自身が選者となって書く**
  - **掲載ページの質そのものがインセンティブ**: 選者にとって自分の名前が載るページは名刺・ポートフォリオの一部になる。安っぽいページには名前を出したくないし、美しいページなら自分から共有する。**UI/UXへの投資は、そのままインセンティブへの投資である**
  - **最初の3人はインセンティブでは動かない**。無名メディアが提供できる露出はゼロであり、「掲載されれば宣伝になります」は記事0本の段階では嘘。**既存の関係（指導教員・ゼミの先輩・研究会の知人）で取るしかない**。3人取れれば4人目以降には「こういう方々が参加しています」と言える
- 乗る波: 埋もれた良書の発掘・キュレーション需要、および X 上の読書・専門家コミュニティ（原則13）
- 検証方法:
  - **MVP 前**: 静的ページ1本（または note）で「〇〇分野・専門家1人の選書」を公開し、X で反応（RT・保存・返信）を測る。サイト構築は反応が出てから
  - **コールドスタート対策**: ネット上で既に公開されている選書（出典リンク付き・引用範囲）を集約して初期の母数を作り、そこに DM 取材の一次情報を積み増す

## 成功指標
- **90日以内に、DM 取材による一次情報の選者記事を10本公開する**
- **90日以内に、メール登録読者300人**
- **1記事あたりの選者本人による X 共有率 50%以上**（選者が共有したくなる品質かどうかの代理指標）
- 上記いずれかが未達の場合、フェーズ2（投稿機能・SNS化）には進まない

## 未検証リスク・意図的に破った原則
- **【最大のリスク】収益手段が特定できていない**: 広告・アフィリエイト・有料コンテンツすべてを検証の結果却下した。現時点で「このプロダクトに金を払う人」は存在が確認されていない。オーナー判断により「読者を集めてから収益手段を探す」方針を採用したが、規模が出ても支払者が現れない可能性は残る
- **意図的に破った原則 1・8（無料プランを持たない / ハードペイウォール）**: 理由 — オーナーが「読者を集めてから収益手段を探す」を選択。無料読者の課金転換率は3%未満というリスクを認識した上での判断
- **意図的に破った原則 27・32（買い切り / 競合より高く売る）**: 理由 — 価格が0円のため適用外。将来収益化する場合は再検討する
- **【新規リスク・2026-08-05】コンセプト変更による差別化の希薄化**: 「学術書」という狭く明確なニッチ（日本語圏に同型メディアが存在しないことを確認済み）から、「知られざる面白い本」という**競合が飽和した領域**（X・note・YouTube・書店フェア）へ広げた。原則11（一つのことだけをする）と原則19（誰も見たことがないもの）は後退している。
  - **緩和策**: 選者の専門性という条件を維持し、「その道を極めた人しか知らない本」に限定することで、単なる「隠れた名著紹介」との差を作る
