# Skrinia（仮称）

その領域に詳しい人が、**有名ではないけれど本当に面白い本を5冊**選んで紹介するメディア。

このREADMEを読めばメディアの運用（記事の追加・画像の登録・公開）ができるようにしてある。
事業判断の経緯や設計の根拠は `.dev/` にある（`business-plan.md` / `requirements.md` / `design-brief.md` / `plan.md` / `build-log.md`）。

> **サービス名は未確定。** 現在は `src/config.ts` の `SITE.name` に仮の名前が入っている。
> ここ1箇所を書き換えれば全ページに反映される。

## 1. すぐ動かす

```bash
npm install
npm run dev      # http://localhost:4321
npm run build    # dist/ に静的サイトを生成
npm run preview  # ビルド結果を確認
```

技術構成: **Astro**（静的生成）/ **Tailwind CSS v4** / **Cloudflare Pages**（無料枠で商用利用が許されるため）。
**データベース・管理画面・ログイン機能は無い。** 記事はMarkdownファイルで管理する。

## 2. 記事を書いて公開する

### 手順は3ステップだけ

1. `src/content/interviews/` に `.md` ファイルを1つ作る
2. frontmatter を書く（[全項目は §3](#3-frontmatter-の全項目)）
3. `git push` する → Cloudflare Pages が自動でビルド・公開

**ファイル名は自由**（URLには影響しない）。慣例として `<選者のローマ字>-<分野>.md` にしている。
例: `yamada-behavioral-economics.md`

**URLは frontmatter の `slug` で決まる。** `slug: yamada-behavioral-economics` なら
記事URLは `/yamada-behavioral-economics/` になる。

### 記事の本文について

frontmatter の外（`---` の下）に書いたMarkdownが、**5冊のカードの上に置かれる導入文**になる。
まとめの文章もここに書く。段落・見出し（`##`）・引用（`>`）が使える。

各書籍の説明は本文ではなく **frontmatter の `reason` / `whyUnknown`** に書く。
本文に書いてもカードには表示されない。

### 最小の記事テンプレート

```markdown
---
title: 山田太郎が選ぶ、行動経済学の5冊
slug: yamada-behavioral-economics
publishedAt: 2026-08-04
description: 一覧・検索・OGP・meta description に使われる要約。120字程度。
topic: 行動経済学
keywords:
  - 行動経済学
  - 意思決定
selector:
  name: 山田太郎
  reading: やまだ たろう
  affiliation: ○○大学 経済学部 教授
  bio: どういう研究をしている人かを1〜2文で。
  credentials: 公開された実績。論文・著書・担当した本・職歴など。読者が検証できること。
  links:
    x: yamada_t
    site: https://example.ac.jp/yamada
books:
  - title: ファスト＆スロー（上）
    author: ダニエル・カーネマン
    translator: 村井章子
    publisher: 早川書房
    year: 2014
    isbn: "9784150504106"
    reason: |
      なぜこの本を薦めるのか。300〜600字。
    whyUnknown: |
      なぜこの本が知られていないのか。150〜300字。
  # ここに残り4冊。合計で必ず5冊
---

導入文をここに書く。選者がどういう人で、この5冊で何が見えるのか。3〜5段落。

> 選者の発言を引用として置くこともできる。

まとめもここに書く。
```

### 選者に寄稿を依頼するときのテンプレート

`.dev/business-plan.md` で「**寄稿がデフォルト、相手が望めば取材も受ける**」と決めている。
依頼時は以下を必ず伝えること。

- **5冊ちょうど**（4冊でも6冊でもサイトがビルドできない）
- 各冊の**選書理由**（300〜600字）
- 各冊の**「この本が知られていない理由」**（150〜300字）← **このメディアの核**
- 選者ご自身の**所属・略歴・公開された実績**
- Xアカウント（任意。露出になるので聞いておく）
- 「読みやすさのため体裁を整えさせていただく場合があります」と**事前に伝える**

## 3. frontmatter の全項目

ビルド時に型チェックされる（`src/content.config.ts`）。
**必須項目が欠けている・5冊でない・ISBNの形式が違う場合、ビルドが失敗して公開されない。**
壊れた記事が本番に出ることはない。

### 記事本体

| 項目 | 必須 | 型 | 説明 |
|---|---|---|---|
| `title` | ✅ | 文字列 | 記事タイトル |
| `slug` | ✅ | 文字列 | URLになる。半角英数とハイフン推奨 |
| `publishedAt` | ✅ | 日付 | `2026-08-04` 形式。並び順に使う |
| `description` | ✅ | 文字列 | 一覧・検索・OGP・meta description。120字程度 |
| `topic` | ✅ | 文字列 | 分野名。`/topics/<分野名>/` が自動生成される |
| `keywords` | — | 文字列の配列 | SEO用 |
| `selector` | ✅ | 下記 | 選者 |
| `books` | ✅ | 下記 × **ちょうど5件** | 5冊 |

### `selector`（選者）

| 項目 | 必須 | 説明 |
|---|---|---|
| `name` | ✅ | 氏名。**これが選者ページのURLになる**（同姓同名は同一人物として扱われる） |
| `reading` | — | ふりがな |
| `affiliation` | ✅ | 所属 |
| `bio` | ✅ | 略歴 |
| `credentials` | ✅ | **公開された実績。** 「なぜこの人の推薦を信じるのか」の根拠。読者が検証できる内容にする |
| `links.x` | — | Xのハンドル。**`@` は付けない**（`yamada_t` と書く） |
| `links.site` | — | 個人サイト等のURL |

### `books`（必ず5件）

| 項目 | 必須 | 説明 |
|---|---|---|
| `title` | ✅ | 書名 |
| `author` | ✅ | 著者 |
| `translator` | — | 訳者。あれば「著者 / 訳者 訳」と表示される |
| `publisher` | ✅ | 出版社 |
| `year` | ✅ | 刊行年（数値。`2014` のようにクォートなし） |
| `isbn` | ✅ | **ハイフンなしの13桁。必ずクォートで囲む**（`"9784150504106"`） |
| `reason` | ✅ | 選書理由。300〜600字 |
| `whyUnknown` | ✅ | **この本が知られていない理由。** 150〜300字 |

**`isbn` は書影の取得と将来のリンクに使う結合キー。** 書影を出さない本でも必ず正しい値を入れること。

**`whyUnknown` は必須。** 空欄にできない仕様にしてあるのは、
「有名な本が混ざること」への歯止めを運用ではなく構造で効かせるため。
書く時点で「なぜ埋もれているのか」を説明する必要があるので、自然にフィルタが働く。

## 4. 画像の置き場所

**画像は原則すべて任意。** 用意しなくてもサイトは成立するように作ってある。

| 種類 | 置き場所 | ファイル名 | 用意しない場合 |
|---|---|---|---|
| **書影** | `public/covers/` | `<13桁ISBN>.jpg` | 書名を**縦組み**にした面が出る（和書の装丁のように見える） |
| **記事サムネイル** | `public/thumbnails/` | `<slug>.jpg` | その記事のOGP画像を自動で流用する |
| **OGP画像** | — | — | **自動生成**。用意不要 |
| 選者の顔写真 | （未実装） | — | 写真なし前提で設計してある |

`.jpg` `.jpeg` `.png` `.webp` を認識する。原則 `.jpg`。

### 書影の登録: `public/covers/9784150504106.jpg`

書影は以下の順で解決される。**上にあるものが優先される。**

1. `public/covers/<ISBN>.jpg`（自分で登録した画像）
2. openBD API
3. Google Books API
4. 縦組みの書名（フォールバック）

**実測では2と3でほとんど取れない**（サンプル10冊で openBD 2件、Google Books 0件）。
つまり**書影を出したい本は、基本的に自分で登録することになる。**

> ### ⚠️ 書影の登録には出版社の許諾が必要
>
> `public/covers/` に置いた画像は自サイトから配信される。これは表紙デザインの
> **複製および公衆送信**にあたり、外部APIのURLを参照するのとは法的な扱いが違う。
>
> 1. **出版社へ書影掲載の許諾をメールで取得する**（掲載先URL・用途・期間を明記し、返信は保存する）
> 2. **書誌情報と出典を記事に明記する**（自動で表示される）
> 3. **削除要請には即応する**（該当ファイルを消して再デプロイ。窓口は `/contact`）
>
> **許諾が取れていない書影を置かないこと。** 詳細は `public/covers/README.md`。

### 記事サムネイルの登録: `public/thumbnails/<slug>.jpg`

トップページの記事カード（236×150）に使われる。
**用意しなければOGP画像が自動で使われる**ので、通常は不要。

## 6. 設定と環境変数

### `src/config.ts`

サイト全体の設定はここ1箇所にまとまっている。**コード中にサイト名やURLを直接書かないこと。**

| 項目 | 説明 | 現状 |
|---|---|---|
| `SITE.name` | サービス名 | **仮の名前。要変更** |
| `SITE.url` | 本番URL。OGPの絶対URL生成に使う | **仮の値。要変更** |
| `SITE.description` | サイトの説明 | |
| `SITE.contactEmail` | 取材依頼・削除要請の窓口 | **要設定** |
| `SITE.applyFormUrl` | 選者応募フォーム（Tally等）のURL | 空なら `/apply` は「準備中」表示 |
| `SITE.newsletterActionUrl` | メール配信サービスの登録フォームURL | 空なら登録欄は「準備中」表示 |

### 環境変数

`.env` に書く（gitには入らない）。

```
PUBLIC_CF_BEACON_TOKEN=xxxxx   # Cloudflare Web Analytics のトークン
```

未設定なら解析スクリプトは出力されない。**Cookieを使わないので同意バナーは不要。**

### 色や書体を変えるとき

`src/styles/global.css` の `@theme` を編集する。**コンポーネント側では色を直接指定していない**ので、
ここを1箇所変えれば全ページに反映される。

## 7. デプロイ

**Cloudflare Pages**（無料枠で商用利用が許されている。Vercel HobbyとGitHub Pagesは規約で商用利用を禁止しているため使えない）。

1. Cloudflare ダッシュボードで Pages プロジェクトを作り、このリポジトリを接続する
2. ビルド設定
   - ビルドコマンド: `npm run build`
   - 出力ディレクトリ: `dist`
3. 環境変数に `PUBLIC_CF_BEACON_TOKEN` を設定する
4. `git push` すると自動でビルド・公開される

## 8. 公開前チェックリスト

### 記事を1本追加したとき

- [ ] `npm run build` が通る（**5冊でない・ISBNの形式違い・必須項目の欠けはここで失敗する**）
- [ ] 記事ページを開いて、5冊のカードと「この本が知られていない理由」が出ている
- [ ] 選者名・所属・実績が正しい
- [ ] **公開前に選者本人へ原稿を確認してもらう**
- [ ] 公開後、**X Card Validator でカードの表示を確認する**
      → OGP画像はXに強くキャッシュされる。**後から差し替えても反映されない**ので必ず初回に確認する

### サイトを初めて公開する前

- [ ] `src/config.ts` の `SITE.name` / `SITE.url` / `SITE.contactEmail` を実際の値にする
- [ ] `/about` の運営者情報（氏名・所属・経歴）を書く
      → **面識のない相手に取材を依頼したとき、必ず見られるページ。ここの信用が取材の可否を決める**
- [ ] `/contact` のメールアドレスが実在するものになっている（削除要請の窓口でもある）
- [ ] `src/pages/_dev-og.astro` `_dev-bookcard.astro`（確認用ページ）を削除する
- [ ] Google リッチリザルトテストで JSON-LD にエラーが出ないことを確認する
- [ ] Lighthouse（モバイル）で Performance 90以上 / Accessibility 95以上

## 9. よくある詰まりどころ

### ビルドが `expected array to have >=5 items` で失敗する
**書籍が5冊ちょうどになっていない。** これは仕様。「5冊」がこのメディアの商品性そのものなので、
型レベルで強制している。4冊や6冊の記事は公開できない。

### ビルドが `isbn は13桁の数字のみ` で失敗する
ISBNにハイフンが入っているか、クォートで囲んでいない。
`isbn: "9784150504106"` の形にする（`978-4-15-050410-6` は不可）。

### 書影が出ない
仕様どおり。**実測で8割の本は自動取得できない。** 出したい場合は許諾を取ったうえで
`public/covers/<ISBN>.jpg` に置く。置かない場合の縦組み表示は「壊れ」ではなく意図した見た目。

### 分野ページのURLに日本語が入る
仕様。`/topics/行動経済学/` のように日本語のまま扱っている（リンク生成時にURLエンコードされる）。

### 選者ページが分かれてしまう / 統合されてしまう
選者の同一性は **`selector.name` の完全一致**で判定している。
表記を揺らすと別人になり、同姓同名は同一人物になる。

### OGP画像を修正したのにXで古いまま
Xがカード画像を強くキャッシュしているため。**Card Validator でキャッシュを更新する**か、
`slug` を変えて別URLにする。これを避けるため、**初回公開時に必ず Validator を通すこと。**
